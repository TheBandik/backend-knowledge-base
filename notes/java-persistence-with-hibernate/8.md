# Глава 8. Продвинутые приёмы отображения связей

> Зачем читать: `@OneToOne` и `@ManyToMany` нужны реже, но спрашивают часто. Здесь же – когда стоит заменить `@ManyToMany` промежуточной сущностью, что такое составной PK как FK и почему `@OneToMany` с `List` – почти всегда плохая идея.

---

## 8.1. Связь `@OneToOne`

По умолчанию `@OneToOne` – `EAGER`. Всегда менять на `LAZY`, но с оговоркой.

**Ловушка lazy-загрузки:** `@OneToOne(optional = true)` не поддерживает lazy через прокси – Hibernate должен убедиться, что запись вообще существует, а значит, всё равно пойдёт в БД. Обходы: `optional = false` или байт-код инструментирование (глава 12).

### 8.1.1. Общий первичный ключ (`@PrimaryKeyJoinColumn`)

Обе таблицы `USERS` и `ADDRESS` имеют одинаковое значение PK. `USERS.ID` = `ADDRESS.ID`.

```java
@Entity
@Table(name = "USERS")
public class User {
    @Id
    protected Long id; // присваивается приложением вручную

    @OneToOne(fetch = FetchType.LAZY, optional = false)
    @PrimaryKeyJoinColumn
    protected Address shippingAddress;
}
```

**Проблемы:** нужен генератор, который даёт значение до INSERT; ручное присваивание одинакового ID; lazy работает только при `optional = false`.

### 8.1.2. Генератор внешнего ключа (двунаправленный вариант)

В классе `Address` – специальный Hibernate-генератор `"foreign"`, берущий значение PK из связанного объекта `User`:

```java
@Entity
public class Address {
    @Id
    @GeneratedValue(generator = "addressKeyGenerator")
    @GenericGenerator(
        name = "addressKeyGenerator",
        strategy = "foreign",
        parameters = @Parameter(name = "property", value = "user")
    )
    protected Long id;

    @OneToOne(optional = false)
    @PrimaryKeyJoinColumn
    protected User user;
}
```

В `User` добавляется `mappedBy = "user"` и `CascadeType.PERSIST` – Hibernate сам сохранит `Address` и присвоит идентификатор.

### 8.1.3. Столбец внешнего ключа + UNIQUE (рекомендованный вариант)

Столбец `SHIPPINGADDRESS_ID` в `USERS` с ограничением `UNIQUE`.

```java
@OneToOne(fetch = FetchType.LAZY, optional = false, cascade = CascadeType.PERSIST)
@JoinColumn(unique = true) // по умолчанию SHIPPINGADDRESS_ID
protected Address shippingAddress;
```

Lazy работает корректно: значение FK известно при загрузке `USERS`. Hibernate создаёт прокси, не делая дополнительный SELECT.

### 8.1.4. Промежуточная таблица (`@JoinTable`) для необязательной связи

Когда связь необязательная и не хочется NULL-столбца:

```java
@OneToOne(fetch = FetchType.LAZY)
@JoinTable(
    name = "ITEM_SHIPMENT",
    joinColumns = @JoinColumn(name = "SHIPMENT_ID"),
    inverseJoinColumns = @JoinColumn(name = "ITEM_ID", nullable = false, unique = true)
)
protected Item auction;
```

Если запись в `ITEM_SHIPMENT` есть – связь существует. `UNIQUE` на `ITEM_ID` гарантирует один к одному.

**Итого по выбору стратегии `@OneToOne`:**

| Ситуация | Стратегия |
|---|---|
| Одна сущность всегда сохраняется раньше и является источником PK | Общий PK + `foreign` генератор |
| Стандартный случай | Столбец FK + `UNIQUE` |
| Необязательная связь, нет NULL-столбцов | Таблица соединения |

## 8.2. Продвинутые варианты `@OneToMany`

### Bag вместо Set

`Collection<Bid>` + `ArrayList` – лучшая производительность для `@OneToMany(mappedBy=...)`: добавление элемента не требует загрузки всей коллекции.

```java
@OneToMany(mappedBy = "item")
public Collection<Bid> bids = new ArrayList<>();
```

Для `Set` и `List` Hibernate загружает всю коллекцию при добавлении нового элемента. Bag этого не делает.

### Список с `@OrderColumn` (однонаправленный)

Если нужен двунаправленный `List` – нужно дважды отображать `@JoinColumn` и запрещать запись на стороне `@ManyToOne`:

```java
// В Item:
@OneToMany
@JoinColumn(name = "ITEM_ID", nullable = false)
@OrderColumn(name = "BID_POSITION", nullable = false)
public List<Bid> bids = new ArrayList<>();

// В Bid:
@ManyToOne
@JoinColumn(name = "ITEM_ID", updatable = false, insertable = false)
@NotNull
protected Item item;
```

На практике хранить порядок в БД почти никогда не нужно. Используй запросы с `ORDER BY`.

### Необязательная связь через таблицу соединения

```java
// В Item:
@ManyToOne(fetch = FetchType.LAZY)
@JoinTable(
    name = "ITEM_BUYER",
    joinColumns = @JoinColumn(name = "ITEM_ID"),
    inverseJoinColumns = @JoinColumn(nullable = false) // BUYER_ID
)
protected User buyer;

// В User:
@OneToMany(mappedBy = "buyer")
protected Set<Item> boughtItems = new HashSet<>();
```

Нет NULL-столбцов в схеме. Если записи в `ITEM_BUYER` нет – товар не куплен.

### `@OneToMany` во встраиваемом классе

Встраиваемый класс может иметь `@OneToMany`. FK-столбец берёт значение ID из сущности-владельца:

```java
@Embeddable
public class Address {
    @OneToMany
    @JoinColumn(name = "DELIVERY_ADDRESS_USER_ID", nullable = false)
    protected Set<Shipment> deliveries = new HashSet<>();
}
```

По умолчанию (без `@JoinColumn`) – таблица соединения.

## 8.3. `@ManyToMany` и промежуточная сущность

### Простой `@ManyToMany`

```java
// Category (владелец):
@ManyToMany(cascade = CascadeType.PERSIST)
@JoinTable(
    name = "CATEGORY_ITEM",
    joinColumns = @JoinColumn(name = "CATEGORY_ID"),
    inverseJoinColumns = @JoinColumn(name = "ITEM_ID")
)
protected Set<Item> items = new HashSet<>();

// Item (отображаемая сторона):
@ManyToMany(mappedBy = "items")
protected Set<Category> categories = new HashSet<>();
```

`CascadeType.ALL`, `REMOVE` и `orphanRemoval` для `@ManyToMany` **не имеют смысла** – обе стороны независимые сущности.

### Промежуточная сущность – предпочтительный вариант

Когда связывающей таблице нужны дополнительные столбцы (и они рано или поздно появятся):

```java
@Entity
@Table(name = "CATEGORY_ITEM")
@Immutable
public class CategorizedItem {

    @Embeddable
    public static class Id implements Serializable {
        @Column(name = "CATEGORY_ID") protected Long categoryId;
        @Column(name = "ITEM_ID")     protected Long itemId;
        // equals() + hashCode()
    }

    @EmbeddedId
    protected Id id = new Id();

    @Column(updatable = false) @NotNull protected String addedBy;
    @Column(updatable = false) @NotNull protected Date addedOn = new Date();

    @ManyToOne
    @JoinColumn(name = "CATEGORY_ID", insertable = false, updatable = false)
    protected Category category;

    @ManyToOne
    @JoinColumn(name = "ITEM_ID", insertable = false, updatable = false)
    protected Item item;

    public CategorizedItem(String addedBy, Category category, Item item) {
        this.addedBy = addedBy;
        this.category = category;
        this.item = item;
        this.id.categoryId = category.getId();
        this.id.itemId = item.getId();
        category.getCategorizedItems().add(this);
        item.getCategorizedItems().add(this);
    }
}
```

Двунаправленная навигация:
```java
// Category и Item:
@OneToMany(mappedBy = "category")
protected Set<CategorizedItem> categorizedItems = new HashSet<>();
```

### Тройная связь через `@Embeddable` (без промежуточной сущности)

```java
@Embeddable
public class CategorizedItem {
    @ManyToOne
    @JoinColumn(name = "ITEM_ID", nullable = false, updatable = false)
    protected Item item;

    @ManyToOne
    @JoinColumn(name = "USER_ID", updatable = false)
    @NotNull
    protected User addedBy;

    @Temporal(TemporalType.TIMESTAMP)
    @Column(updatable = false) @NotNull
    protected Date addedOn = new Date();
}

// Category:
@ElementCollection
@CollectionTable(name = "CATEGORY_ITEM",
    joinColumns = @JoinColumn(name = "CATEGORY_ID"))
protected Set<CategorizedItem> categorizedItems = new HashSet<>();
```

**Плюс:** неявный жизненный цикл – добавление/удаление из коллекции без `persist()`/`remove()`.
**Минус:** нет двунаправленной навигации от `Item`.

## Главное

- `@OneToOne` по умолчанию `EAGER` – всегда менять на `LAZY`; `optional=true` + lazy не работает без байт-кода
- Три стратегии `@OneToOne`: общий PK, столбец FK + UNIQUE (рекомендован), таблица соединения (для необязательной)
- Bag (`Collection<T>`) для `@OneToMany(mappedBy=...)` – лучшая производительность; добавление без загрузки коллекции
- `@OneToMany` с `@OrderColumn` дорого при изменениях; двунаправленный `List` требует `insertable=false, updatable=false` на стороне `@ManyToOne`
- Необязательная `@OneToMany` → `@JoinTable` вместо NULL-столбца
- `@ManyToMany` скрывает связывающую таблицу; `CascadeType.ALL/REMOVE/orphanRemoval` для `@ManyToMany` не имеют смысла
- Вместо `@ManyToMany` почти всегда лучше промежуточная сущность с двумя `@ManyToOne` и `@EmbeddedId`
- Тройная связь через `@Embeddable` + `@ElementCollection` – проще кода, но нет двунаправленной навигации
- Перед любым сложным отображением коллекции спроси себя: а нужна ли она вообще, или хватит запроса?
