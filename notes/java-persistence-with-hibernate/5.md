# Глава 5. Отображение типов-значений

> Зачем читать: здесь разобраны все детали отображения полей – базовые типы, встраиваемые компоненты, конвертеры. Без этого невозможно грамотно проектировать хранимые классы. Часто спрашивают на собеседованиях про `@Embeddable`, `@Transient`, `@Lob`, `AttributeConverter`.

---

## 5.1. Отображение полей базовых типов

По умолчанию Hibernate хранит **все** поля класса, если `@Id` стоит над полем (прямой доступ к полям). Исключения:

- Поле помечено `@Transient` или ключевым словом `transient` – не хранится
- Поле неизвестного типа → Hibernate выбросит исключение при старте

**Конфигурация через исключение:** не нужно ничего дополнительно аннотировать, чтобы поле хранилось. Настройка нужна только когда что-то надо изменить.

### Основные аннотации переопределения

**`@Basic`** – минимальная аннотация поля. Практически бесполезна, но явно объявляет поле хранимым:
```java
@Basic(optional = false)
BigDecimal initialPrice; // optional=false → NOT NULL в DDL
```

**`@Column`** – более полезна; переопределяет имя столбца и constraints:
```java
@Column(name = "START_PRICE", nullable = false)
BigDecimal initialPrice;
```

**`@NotNull` (Bean Validation)** – рекомендованный вариант для NOT NULL, работает и на уровне Java-валидации, и в DDL.

> Три способа объявить NOT NULL: `@Basic(optional=false)`, `@Column(nullable=false)`, `@NotNull`. Все ведут к одному результату в DDL, но `@NotNull` дополнительно позволяет валидировать вручную.

### 5.1.1. Стратегии доступа (`@Access`)

По умолчанию стратегия определяется положением `@Id`:
- `@Id` над **полем** → Hibernate обращается напрямую ко всем полям (`AccessType.FIELD`)
- `@Id` над **геттером** → Hibernate использует методы доступа (`AccessType.PROPERTY`)

Переопределение для всего класса:
```java
@Entity
@Access(AccessType.PROPERTY)
public class Item { ... }
```

Переопределение для отдельного поля:
```java
@Id // → доступ к полям по умолчанию для класса
protected Long id;

@Access(AccessType.PROPERTY) // → только это поле через геттер/сеттер
@Column(name = "ITEM_NAME")
protected String name;

public String getName() { return name; }
public void setName(String name) {
    this.name = !name.startsWith("AUCTION: ") ? "AUCTION: " + name : name;
}
```

**Зачем нужно:** когда нужна бизнес-логика в геттере/сеттере, которую Hibernate должен вызывать при загрузке/сохранении.

### 5.1.2. Вычисляемые поля (`@Formula`)

Только для чтения. SQL вычисляется при каждом SELECT, не участвует в INSERT/UPDATE:

```java
@org.hibernate.annotations.Formula(
    "substr(DESCRIPTION, 1, 12) || '...'"
)
protected String shortDescription;

@org.hibernate.annotations.Formula(
    "(select avg(b.AMOUNT) from BID b where b.ITEM_ID = ID)"
)
protected BigDecimal averageBidAmount;
```

Неквалифицированные имена столбцов ссылаются на таблицу класса-владельца. SQL передаётся в БД как есть – привязка к конкретной СУБД.

### 5.1.3. Преобразователи столбцов (`@ColumnTransformer`)

Произвольный SQL при чтении и записи значения:

```java
@Column(name = "IMPERIALWEIGHT")
@org.hibernate.annotations.ColumnTransformer(
    read = "IMPERIALWEIGHT / 2.20462",
    write = "? * 2.20462"
)
protected double metricWeight;
```

Hibernate применяет `read`-выражение в SELECT и `write`-выражение в INSERT/UPDATE. В запросах JPQL тоже применяется: `where i.metricWeight = :w` транслируется в `where IMPERIALWEIGHT / 2.20462 = ?`.

> **Подводный камень:** функция в WHERE → нельзя использовать индекс → полное сканирование таблицы.

### 5.1.4. Значения, генерируемые БД (`@Generated`)

Когда значение присваивает триггер или дефолт в БД, Hibernate выполняет SELECT сразу после INSERT/UPDATE:

```java
@Temporal(TemporalType.TIMESTAMP)
@Column(insertable = false, updatable = false) // не включать в INSERT/UPDATE
@org.hibernate.annotations.Generated(
    org.hibernate.annotations.GenerationTime.ALWAYS // после INSERT и UPDATE
)
protected Date lastModified;

@Column(insertable = false)
@org.hibernate.annotations.ColumnDefault("1.00") // значение в DDL
@org.hibernate.annotations.Generated(
    org.hibernate.annotations.GenerationTime.INSERT // только после INSERT
)
protected BigDecimal initialPrice;
```

`GenerationTime.ALWAYS` – после каждого INSERT и UPDATE. `GenerationTime.INSERT` – только после INSERT.

### 5.1.5. Поля даты и времени

JPA требует `@Temporal` для `java.util.Date` и `java.util.Calendar`:

```java
@Temporal(TemporalType.TIMESTAMP)
@Column(updatable = false)
@org.hibernate.annotations.CreationTimestamp // Hibernate-расширение
protected Date createdOn;
```

`TemporalType`: `DATE`, `TIME`, `TIMESTAMP`.

**Ловушка с `java.util.Date`:** при загрузке из БД Hibernate возвращает `java.sql.Timestamp` (подкласс), а не `java.util.Date`. Это ломает `equals()`:
```java
// Никогда не сравнивай так:
aDate.equals(bDate);
// Правильно:
aDate.getTime() == bDate.getTime()
```

Классы `java.time.*` (Java 8) поддерживаются Hibernate нативно без `@Temporal`.

### 5.1.6. Перечисления

```java
@Enumerated(EnumType.STRING) // рекомендуется
protected AuctionType auctionType = AuctionType.HIGHEST_BID;
```

По умолчанию – `ORDINAL` (числовой индекс). **Опасно:** добавление нового значения в середину enum сдвинет индексы и сломает данные в БД. Всегда использовать `EnumType.STRING`.

## 5.2. Встраиваемые компоненты (`@Embeddable`)

Тип-значение без собственной идентичности. Все столбцы встраиваемого класса хранятся в таблице сущности-владельца.

### Объявление встраиваемого класса

```java
@Embeddable
public class Address {
    @NotNull
    @Column(nullable = false)
    protected String street;

    @NotNull
    @Column(nullable = false, length = 5)
    protected String zipcode;

    @NotNull
    @Column(nullable = false)
    protected String city;

    protected Address() {} // обязателен для Hibernate

    public Address(String street, String zipcode, String city) { ... }
}
```

**Важно:** `@NotNull` над полями `@Embeddable` **не генерирует** `NOT NULL` в DDL. Нужна `@Column(nullable = false)`. Это баг Hibernate Validator (HVAL-3).

Класс-владелец:
```java
@Entity
@Table(name = "USERS")
public class User {
    protected Address homeAddress; // @Embedded не обязателен, достаточно @Embeddable на классе
}
```

### Два встраиваемых поля одного типа – `@AttributeOverrides`

```java
@Embedded // необязательно, но явно
@AttributeOverrides({
    @AttributeOverride(name = "street", column = @Column(name = "BILLING_STREET")),
    @AttributeOverride(name = "zipcode", column = @Column(name = "BILLING_ZIPCODE", length = 5)),
    @AttributeOverride(name = "city",   column = @Column(name = "BILLING_CITY"))
})
protected Address billingAddress;
```

> **Ловушка:** `@AttributeOverride` перекрывает **все** аннотации JPA из встраиваемого класса, включая `nullable`. Переопределённые столбцы автоматически допускают NULL.

### Вложенные компоненты

```java
@Embeddable
public class Address {
    protected String street;

    @AttributeOverrides(
        @AttributeOverride(name = "name", column = @Column(name = "CITY", nullable = false))
    )
    protected City city; // встраиваемый в встраиваемый
}

@Embeddable
public class City {
    protected String zipcode;
    protected String name;
    protected String country;
}
```

Все поля хранятся в таблице корневой сущности-владельца. Обращение к вложенным атрибутам через точку: `@AttributeOverride(name = "city.zipcode", ...)`.

### Стратегия доступа во встраиваемых классах

Встраиваемый класс наследует стратегию доступа от сущности-владельца. Если `@Id` стоит над полем `User` → все аннотации в `Address` тоже над полями.

### Null-проблема

Если все поля `Address` в строке равны NULL → при загрузке Hibernate вернёт `null` вместо экземпляра `Address` с пустыми полями. Не использовать nullable-столбцы в встраиваемых компонентах.

## 5.3. Встроенные типы и маппинг Java→SQL

Hibernate выбирает SQL-тип автоматически по Java-типу. Ключевые таблицы:

**Числовые:**
| Java тип | SQL тип |
|---|---|
| `int` / `Integer` | `INTEGER` |
| `long` / `Long` | `BIGINT` |
| `double` / `Double` | `DOUBLE` |
| `BigDecimal` | `NUMERIC` |

**Строковые:**
| Java тип | SQL тип / адаптер |
|---|---|
| `String` | `VARCHAR` (255 по умолчанию) |
| `boolean` (yes_no) | `CHAR(1)` → 'Y'/'N' |
| `Class`, `Locale`, `Currency` | `VARCHAR` |

Длина `String` влияет на SQL-тип (диалект-зависимо). Для MySQL: до 65535 → `VARCHAR`, до 16М → `MEDIUMTEXT`, больше → `LONGTEXT`.

**Бинарные / LOB:**
| Java тип | SQL тип |
|---|---|
| `byte[]` | `VARBINARY` |
| `@Lob byte[]` | `BLOB` |
| `@Lob String` | `CLOB` |
| `java.sql.Blob` | `BLOB` (lazy) |
| `java.sql.Clob` | `CLOB` (lazy) |

`@Lob` на `byte[]`/`String` не даёт ленивой загрузки автоматически. Для lazy нужен тип `java.sql.Blob`/`java.sql.Clob` или внедрение в байт-код.

Переопределение типа вручную:
```java
@org.hibernate.annotations.Type(type = "yes_no")
protected boolean verified = false; // сохранится как 'Y'/'N'
```

## 5.4. Конвертеры JPA (`AttributeConverter`)

Стандартный механизм расширения JPA для преобразования значений **одного поля** в **один столбец**.

```java
@Converter(autoApply = true) // применяется ко всем полям типа MonetaryAmount
public class MonetaryAmountConverter
        implements AttributeConverter<MonetaryAmount, String> {

    @Override
    public String convertToDatabaseColumn(MonetaryAmount amount) {
        return amount.toString(); // "11.23 USD"
    }

    @Override
    public MonetaryAmount convertToEntityAttribute(String s) {
        return MonetaryAmount.fromString(s);
    }
}
```

Использование с переопределением:
```java
@NotNull
@Convert(converter = MonetaryAmountConverter.class, disableConversion = false)
@Column(name = "PRICE", length = 63)
protected MonetaryAmount buyNowPrice;
```

При `autoApply = true` аннотация `@Convert` необязательна – конвертер применяется автоматически ко всем полям данного типа.

### Ограничения `AttributeConverter`

- Нельзя применять к `@Id` и полям версии
- Нельзя комбинировать с `@Enumerated` и `@Temporal` – они сами определяют преобразование
- Не поддерживает маппинг в **несколько столбцов**
- Не поддерживает точечную нотацию в JPQL для атрибутов внутри конвертируемого класса

Для встраиваемых классов с конвертером:
```java
@Convert(converter = ZipcodeConverter.class, attributeName = "zipcode")
protected Address homeAddress; // применяется к Address#zipcode
// или "city.zipcode" для вложенных компонентов
```

## 5.5. Пользовательские типы Hibernate (`UserType`)

Когда нужно преобразование в **несколько столбцов** или интеграция с механизмом запросов – стандартных конвертеров JPA недостаточно.

### Интерфейсы расширения (`org.hibernate.usertype`)

| Интерфейс | Назначение |
|---|---|
| `UserType` | Базовый: чтение из `ResultSet`, запись в `PreparedStatement` |
| `CompositeUserType` | Расширяет `UserType`; описывает свойства типа для JPQL |
| `ParameterizedUserType` | Добавляет параметры конфигурации в адаптер |
| `DynamicParameterizedType` | Динамические параметры: имена столбцов, аннотации поля |
| `EnhancedUserType` | Для поддержки типа как идентификатора или селектора |

### Объявление через `@TypeDef` в `package-info.java`

```java
@org.hibernate.annotations.TypeDefs({
    @org.hibernate.annotations.TypeDef(
        name = "monetary_amount_usd",
        typeClass = MonetaryAmountUserType.class,
        parameters = {@Parameter(name = "convertTo", value = "USD")}
    ),
    @org.hibernate.annotations.TypeDef(
        name = "monetary_amount_eur",
        typeClass = MonetaryAmountUserType.class,
        parameters = {@Parameter(name = "convertTo", value = "EUR")}
    )
})
package org.jpwh.converter;
```

Использование:
```java
@org.hibernate.annotations.Type(type = "monetary_amount_usd")
@org.hibernate.annotations.Columns(columns = {
    @Column(name = "BUYNOWPRICE_AMOUNT"),
    @Column(name = "BUYNOWPRICE_CURRENCY", length = 3)
})
protected MonetaryAmount buyNowPrice;
```

> При `CompositeUserType` порядок столбцов в `@Columns` должен соответствовать порядку работы с `ResultSet`/`PreparedStatement` в адаптере – это критично.

## Главное

- `@Transient` / `transient` – исключить поле из хранения
- `@Column(nullable=false)` = `@NotNull` = `@Basic(optional=false)` для NOT NULL; предпочтительнее `@NotNull` из Bean Validation
- **Стратегия доступа:** положение `@Id` определяет FIELD или PROPERTY для всего класса; `@Access` переопределяет для конкретного поля
- `@Formula` – вычисляемое read-only поле, SQL из БД; никогда не участвует в INSERT/UPDATE
- `@ColumnTransformer` – SQL-выражение для read и write одного столбца; применяется и в WHERE-условиях запросов
- `@Generated` – значение присваивает БД; Hibernate делает SELECT после INSERT/UPDATE
- `@Temporal` обязателен для `java.util.Date`; Hibernate возвращает `java.sql.Timestamp`, не `Date` → не использовать `equals()` напрямую
- `@Enumerated(EnumType.STRING)` – всегда; `ORDINAL` по умолчанию опасен при изменении enum
- `@Embeddable` + `@MappedSuperclass` = один тип-значение, одна таблица владельца; `@AttributeOverrides` для нескольких полей одного типа
- `@NotNull` на полях `@Embeddable` **не создаёт** `NOT NULL` в DDL → нужна `@Column(nullable=false)`
- `AttributeConverter` (JPA) – один Java-тип → один столбец; `autoApply=true` применяется глобально; не работает с `@Id`, `@Enumerated`, `@Temporal`
- `UserType` (Hibernate) – несколько столбцов, интеграция с JPQL; настройка через `@TypeDef` в `package-info.java`
