# Глава 2. Создание проекта

> Зачем читать: практическая основа – как устроен Hibernate-проект, что такое `EntityManager`, `SessionFactory`, `Session` и как с ними работать. На собеседовании спрашивают разницу между JPA API и нативным Hibernate API.

## 2.1. Экосистема Hibernate

Hibernate – не просто ORM. Это набор проектов:

- **Hibernate ORM** – ядро, реализация JPA и нативного API. Работает в любой среде (JavaEE, Spring, Swing, Servlet контейнер)
- **Hibernate EntityManager** – реализация стандартного JPA API поверх ORM
- **Hibernate Validator** – реализация Bean Validation (JSR 303)
- **Hibernate Envers** – версионирование и история изменений данных
- **Hibernate Search** – полнотекстовый поиск через Apache Lucene
- **Hibernate OGM** – JPA для NoSQL (key/value, document, graph БД)

## 2.2. JPA API: ключевые компоненты

### Persistence Unit (единица хранения)

Конфигурируется в `META-INF/persistence.xml`. Объединяет:
- соединение с БД (через JNDI `DataSource` или напрямую)
- список хранимых классов
- настройки провайдера

```xml
<persistence-unit name="HelloWorldPU">
    <jta-data-source>myDS</jta-data-source>
    <class>org.jpwh.model.helloworld.Message</class>
    <exclude-unlisted-classes>true</exclude-unlisted-classes>
    <properties>
        <property name="javax.persistence.schema-generation.database.action"
                  value="drop-and-create"/>
        <property name="hibernate.format_sql" value="true"/>
    </properties>
</persistence-unit>
```

**Про логирование SQL:** включить `hibernate.format_sql=true` и `hibernate.use_sql_comments=true` + уровень DEBUG для `org.hibernate.SQL` и `org.hibernate.type.descriptor.sql.BasicBinder`. Это покажет все запросы с параметрами – незаменимо при отладке и оптимизации.

### EntityManagerFactory

- Создаётся один раз при старте приложения
- Потокобезопасна
- Представляет одну единицу хранения
- Создаётся через `Persistence.createEntityManagerFactory("PUName")`

### EntityManager

- Создаётся из фабрики под каждую единицу работы
- НЕ потокобезопасен
- Является контекстом хранения (Persistence Context) – отслеживает все загруженные сущности
- Должен закрываться явно, если создан вручную

### Базовый цикл работы

```java
// Сохранение
UserTransaction tx = TM.getUserTransaction();
tx.begin();
EntityManager em = emf.createEntityManager();
Message message = new Message();
message.setText("Hello World!");
em.persist(message);
tx.commit(); // INSERT выполняется здесь
em.close();

// Загрузка + автоматический UPDATE
tx.begin();
EntityManager em = emf.createEntityManager();
List<Message> messages =
    em.createQuery("select m from Message m").getResultList();
messages.get(0).setText("New text");
tx.commit(); // Hibernate сам выполнит UPDATE (dirty checking)
em.close();
```

**Важно:** изменения сущностей внутри транзакции не нужно сохранять явно – Hibernate сам обнаружит изменения при commit через **dirty checking**.

**Про JPQL:** запрос `"select m from Message m"` – это не SQL. `Message` – имя Java-класса, а не таблицы. Переименование таблицы в маппинге не сломает запрос.

## 2.3. Нативный Hibernate API

Используется редко – только когда нужна функциональность, недоступная через JPA.

| JPA API               | Hibernate аналог   |
|-----------------------|--------------------|
| `EntityManagerFactory` | `SessionFactory`   |
| `EntityManager`        | `Session`          |
| `Persistence.createEntityManagerFactory(...)` | `MetadataSources` → `buildSessionFactory()` |

### Построение SessionFactory

```java
SessionFactory sessionFactory = new MetadataSources(
    new StandardServiceRegistryBuilder()
        .configure("hibernate.cfg.xml").build()
).buildMetadata().buildSessionFactory();
```

Или программно через `StandardServiceRegistryBuilder`:

```java
StandardServiceRegistryBuilder builder = new StandardServiceRegistryBuilder();
builder.applySetting("hibernate.connection.datasource", "myDS")
       .applySetting("hibernate.format_sql", "true");
ServiceRegistry registry = builder.build();

MetadataSources sources = new MetadataSources(registry);
sources.addAnnotatedClass(Message.class);

SessionFactory sf = sources.buildMetadata().buildSessionFactory();
```

### getCurrentSession()

Удобный способ получить `Session`, привязанный к текущей транзакции. Hibernate сам закрывает такую сессию при commit/rollback:

```java
Session session = sessionFactory.getCurrentSession();
session.persist(message);
```

## Главное

- **Persistence Unit** – конфиг в `persistence.xml`; объединяет БД + классы + настройки
- **EntityManagerFactory** – один на приложение, потокобезопасен, дорого создаётся
- **EntityManager** – один на единицу работы, НЕ потокобезопасен, закрывать явно
- **Dirty checking** – Hibernate сам генерирует UPDATE при изменении сущности в транзакции; `em.merge()` / `em.persist()` для обновления не нужны если объект уже managed
- **JPQL** работает с именами Java-классов, не с именами таблиц
- **SessionFactory / Session** – нативный аналог EMF / EM; использовать только при необходимости нативных возможностей Hibernate
- `getCurrentSession()` привязана к транзакции и закрывается автоматически
