# Глава 7. Отображение коллекций и связей между сущностями

> Зачем читать: самые частые вопросы на собеседованиях – `@OneToMany`, `@ManyToOne`, каскадирование, `orphanRemoval`. Здесь же подробно разобраны все виды коллекций типов-значений. Без понимания этой главы невозможно нормально проектировать модель.

---

## 7.1. Когда нужна коллекция, а когда запрос

Коллекцию стоит отображать, если нужно:
- навигационный доступ к данным (`someItem.getImages()`) без ручных запросов
- каскадное сохранение элементов без явного `persist()`
- зависимый жизненный цикл (элементы удаляются вместе с владельцем)

Если ни одно из этого не нужно – проще написать JPQL-запрос: `select img from Image img where img.item = :item`.

> **Частая ошибка новичков:** маппить коллекцию «потому что так принято». Всегда спрашивай себя – зачем эта коллекция именно здесь.

---

## 7.2. Поддерживаемые интерфейсы коллекций

Всегда объявлять через **интерфейс**, инициализировать сразу при объявлении поля:

```java
Set<String> images = new HashSet<>();   // не LinkedList или конкретный тип
```

| Интерфейс | Реализация | Семантика | Стандарт JPA |
|---|---|---|---|
| `Set<T>` | `HashSet` | Без дублей, без порядка | ✅ |
| `SortedSet<T>` | `TreeSet` | Сортировка в памяти | Только Hibernate |
| `List<T>` | `ArrayList` | Порядок хранится в доп. столбце | ✅ |
| `Collection<T>` | `ArrayList` | Bag: дубли, без порядка | ✅ |
| `Map<K,V>` | `HashMap` | Пары ключ/значение | ✅ |
| `SortedMap<K,V>` | `TreeMap` | Сортировка в памяти | Только Hibernate |

Массивы – Hibernate поддерживает, но без обёртки: нет lazy loading, избегать.

## 7.3. Коллекции типов-значений (`@ElementCollection`)

### Set – базовый вариант

```java
@ElementCollection
@CollectionTable(name = "IMAGE",
    joinColumns = @JoinColumn(name = "ITEM_ID"))
@Column(name = "FILENAME")
protected Set<String> images = new HashSet<>();
```

Схема: таблица `IMAGE` с составным PK `(ITEM_ID, FILENAME)`. Дублей быть не может.

### Bag (`Collection`) – с дублями

В JDK нет `BagImpl`. Тип поля `Collection<T>`, реализация `ArrayList`. Нужен суррогатный PK:

```java
@ElementCollection
@CollectionTable(name = "IMAGE")
@Column(name = "FILENAME")
@org.hibernate.annotations.CollectionId(
    columns = @Column(name = "IMAGE_ID"),
    type = @Type(type = "long"),
    generator = Constants.ID_GENERATOR
)
protected Collection<String> images = new ArrayList<>();
```

### List – с хранимым порядком

```java
@ElementCollection
@CollectionTable(name = "IMAGE")
@OrderColumn  // по умолчанию IMAGES_ORDER
@Column(name = "FILENAME")
protected List<String> images = new ArrayList<>();
```

**Ловушка производительности:** удаление из середины списка из 3 элементов → 1 DELETE + 2 UPDATE для сдвига индексов. Вставка в середину → N UPDATE. Дважды подумай перед `List`.

### Map – ключ и значение

```java
@ElementCollection
@CollectionTable(name = "IMAGE")
@MapKeyColumn(name = "FILENAME")   // ключ
@Column(name = "IMAGENAME")        // значение
protected Map<String, String> images = new HashMap<>();
```

PK таблицы – `(ITEM_ID, FILENAME)`.

## 7.4. Сортировка vs упорядочивание

**sorted** – сортировка в **памяти** после загрузки, через `Comparator`:
```java
@SortComparator(ReverseStringComparator.class)
protected SortedMap<String, String> images = new TreeMap<>();

@SortNatural
protected SortedSet<String> images = new TreeSet<>();
```

**ordered** – упорядочивание через **`ORDER BY`** в SQL при загрузке:
```java
@org.hibernate.annotations.OrderBy(clause = "FILENAME desc") // Hibernate: сырой SQL
protected Set<String> images = new LinkedHashSet<>();

@javax.persistence.OrderBy("filename, width DESC") // JPA: имена полей Java-класса
protected Set<Image> images = new LinkedHashSet<>();
```

> `@javax.persistence.OrderBy` работает с именами свойств Java-класса. `@org.hibernate.annotations.OrderBy` принимает сырой SQL, поэтому может использовать SQL-функции: `substring(FILENAME, 0, 3) desc`.

## 7.5. Коллекции компонентов (`@Embeddable`)

Для `Set` компонентов Hibernate строит составной PK из всех NOT NULL столбцов.

**Обязательно:** переопределить `equals()`/`hashCode()` во всех `@Embeddable` классах – сравнение «по значению»:

```java
@Embeddable
public class Image {
    @Column(nullable = false) protected String title;
    @Column(nullable = false) protected String filename;
    protected int width, height;

    @Override public boolean equals(Object o) { /* все поля */ }
    @Override public int hashCode() { /* все поля */ }
}
```

> **Ловушка:** `@NotNull` на поле `@Embeddable` в коллекции **не создаёт** `NOT NULL` в DDL таблицы коллекции. Нужна `@Column(nullable = false)`.

**Ссылка на владельца из компонента:**
```java
@org.hibernate.annotations.Parent
protected Item item; // Hibernate заполняет при загрузке
```

## 7.6. Связь `@ManyToOne` – самая простая и важная

```java
@Entity
public class Bid {
    @ManyToOne(fetch = FetchType.LAZY)  // по умолчанию EAGER – всегда менять!
    @JoinColumn(name = "ITEM_ID", nullable = false)
    protected Item item;
}
```

FK-столбец в таблице `BID`. Всё. Этого достаточно для большинства случаев.

> Можно написать запрос `select b from Bid b where b.item = :item` вместо маппинга коллекции `@OneToMany`. Никогда не маппи `@OneToMany` автоматически «в пару» к `@ManyToOne`.

---

## 7.7. Двунаправленная связь `@OneToMany`

```java
@Entity
public class Item {
    @OneToMany(
        mappedBy = "item",          // имя поля на стороне @ManyToOne
        fetch = FetchType.LAZY      // по умолчанию LAZY – хорошо
    )
    protected Set<Bid> bids = new HashSet<>();
}
```

**Правила:**
- `mappedBy` – обязателен. Указывает поле на «владеющей» стороне (`Bid#item`)
- Сторона `@OneToMany(mappedBy=...)` – только для чтения при сохранении; FK-столбцом управляет `@ManyToOne`
- Обе стороны нужно поддерживать вручную в Java-коде

## 7.8. Каскадирование (`cascade`)

**`CascadeType.PERSIST`** – при `persist()` родителя автоматически вызывается `persist()` для элементов коллекции:

```java
@OneToMany(mappedBy = "item", cascade = CascadeType.PERSIST)
protected Set<Bid> bids = new HashSet<>();
```

**`CascadeType.REMOVE`** – при `remove()` родителя Hibernate загружает коллекцию и удаляет каждый элемент индивидуально. Неэффективно.

**`orphanRemoval = true`** – при удалении ссылки из коллекции (`bids.remove(bid)`) Hibernate автоматически выполнит `DELETE` для «осиротевшего» объекта:

```java
@OneToMany(mappedBy = "item",
    cascade = CascadeType.PERSIST,
    orphanRemoval = true)
protected Set<Bid> bids = new HashSet<>();
```

> **Опасность `orphanRemoval`:** если на удалённый объект есть другие ссылки (например, `User#bids`), данные в памяти станут противоречивыми. Использовать только когда гарантированно нет разделяемых ссылок.

**Эффективное удаление через БД (`@OnDelete`):**
```java
@OneToMany(mappedBy = "item", cascade = CascadeType.PERSIST)
@org.hibernate.annotations.OnDelete(
    action = org.hibernate.annotations.OnDeleteAction.CASCADE
)
protected Set<Bid> bids = new HashSet<>();
```
Генерирует `FOREIGN KEY ... ON DELETE CASCADE` в DDL. Но Hibernate не очищает кэш второго уровня – осторожно.

## Главное

- Коллекцию маппить только когда она реально нужна для навигации или каскадного жизненного цикла; иначе – JPQL-запрос
- Всегда объявлять тип через интерфейс (`Set`, `List`), инициализировать сразу
- `@ElementCollection` обязателен для коллекций типов-значений; `@CollectionTable` и `@Column` – для переопределения имён
- `List` + `@OrderColumn` – дорого при изменениях; дважды подумай
- `sorted` = сортировка в памяти; `ordered` = `ORDER BY` в SQL
- `@Embeddable` в коллекции: обязательны `equals()`/`hashCode()`; `@Column(nullable=false)` для NOT NULL в DDL
- `@ManyToOne` по умолчанию `EAGER` – всегда заменять на `LAZY`
- `mappedBy` на стороне `@OneToMany` – обязателен; эта сторона только для чтения при сохранении
- `CascadeType.REMOVE` неэффективен: загружает коллекцию и удаляет поштучно
- `orphanRemoval = true` – удаляет «осиротевший» объект при удалении из коллекции; опасно при разделяемых ссылках
